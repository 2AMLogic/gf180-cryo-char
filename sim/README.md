# Simulation

Decision 0001 uses the [single-switch DC and AC controls](switch-loading/README.md) and the [powered measurement pad](pad-loading/README.md). These simulations characterize T4 deterministic controls and a seeded four-switch local-mismatch control. Qualification of a physical range requires the matched fixture, pad and bank measurements in [selection and readout](../spec/selection-readout.md).

Both campaigns were replayed on the original GF180D open_pdks revision f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7 and the [official die-precheck build](https://github.com/2AMLogic/gf180-cryo-char/blob/8cb9488d0ff3bb08d72b5f62fc73a53179d65b09/layout/precheck/records/20261126-151012-c937349-die/record.md), revision 792ef67037d74c8c51811eab3ce23cf793491296. The design parameters and pad subcircuit are byte-identical across these installs. The transistor and diode library hash differs. On the precheck PDK, all 120 DC switch rows with ngspice 47 and all 153 pad rows with ngspice 46 regenerated byte-for-byte against the original CSVs. The comparison covers only the simulated device classes and bias points. [Input digests](qualification_pdk.py)

To reproduce both from one simulator, use ngspice 46. Set PDK to the GF180D variant directory of either supported Ciel installation. The original switch and AC campaigns can also be replayed with ngspice 47. With ngspice 47 on this host the complete pad instance rejects the foundry rail MOS-capacitor expression during parsing. The pad runner uses 46.

```sh
python3 sim/switch-loading/measure.py --pdk "$PDK" --ngspice ngspice
python3 sim/switch-loading/measure_ac.py --pdk "$PDK" --ngspice ngspice
python3 sim/pad-loading/measure.py --pdk "$PDK" --ngspice ngspice --jobs 4
```

The [generic harness](harness/README.md) documents the simulation infrastructure.
